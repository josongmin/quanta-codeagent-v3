## 3. SOTA 강화 제안 (별도 — parity 너머 추월)

> §1은 "따라잡기". 아래는 업계 SOTA 패턴으로 갭 위에 얹어 **추월**.

- **S1. 내구성 워크플로(Durable Execution / Temporal 패턴)** — G1·G3 위.
  `WorkflowEvent`를 `(step-id, input-hash)` 키로 저널링 → 재실행 시 **변경 안 된 최장 prefix는 캐시 즉시 반환**, 첫 변경 step부터 라이브. quanta는 content-hash·shadow-odb 보유 → 적합. 비싼 멀티에이전트 run의 crash/edit-resume.

- **S2. 워크플로+Fleet을 OTel span으로 일원화** — G2·G3 묶기.
  각 phase/agent를 OpenTelemetry span으로(quanta `src/observability/otel`). fleet·진척이 **하나의 trace 트리**. "왜 멈췄나"가 span event로 자연 표현.

- **S3. 예산 인지 fan-out** — G1.
  fan-out 폭을 토큰 예산에 스케일(`while budget.remaining()>X`). `budget-ledger` 노출 → workflow builder 동적 깊이. 비용 하드실링.

- **S4. 품질 하니스를 워크플로 라이브러리 노드로** — G1.
  loop-until-dry / N-skeptic 적대검증 / judge-panel을 **빌트인 워크플로 프리미티브**로. 사용자가 spec 안 짜도 호출.

- **S5. Fleet = 슈퍼바이저 트리 + 백프레셔(Erlang/OTP)** — G2.
  재시작 정책 가진 supervisor tree + **전 종류 통합 동시성 거버너**(in-proc cap 너머). 폭주/행 자동격리.

- **S6. Fleet "why-stuck" 진단 열** — G2 (북극성 핵심).
  각 행에 blocked-reason(waiting-approval / rate-limited / waiting-tool / waiting-subagent). S2 span event가 피드.

- **S7. 서명된 capability deep-link(macaroon/JWT)** — G4.
  URI가 스코프드·서명된 권한(repo·verb·TTL) 운반 → 권한 상승 불가. capability-URL 패턴. 임의 페이지 트리거 차단의 정공법.

- **S8. origin 신뢰 tier + JIT consent(모바일 권한 모델)** — G5.
  trusted/sensitive/untrusted 3-tier + origin별 첫 민감 액션에 just-in-time 동의. method-allowlist × origin-tier 2D.

- **S9. 저장형 워크플로 버전 핀·서명·dry-run** — G1.
  saved workflow 버전 동결(bench preset versioned-selector 패턴 재사용) + 신뢰 소스 서명 + 실행 전 dry-run 프리뷰. 공급망/재현성.
