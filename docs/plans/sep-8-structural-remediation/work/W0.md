## W0.5 MCP policy (frozen — R11 worker input)

### Ready modes

- `dxt-ready-line`: first stdout line is a sentinel, not JSON-RPC. Default for DXT/plugin spawn. Existing bun-spawner first-line consume stays this mode.
- `process-ready`: spawn + stdio connected is ready. Do **not** consume the first stdout line. Standard MCP stdio `initialize` is owned by `McpClient` core.

### Protocol owner

- Isolated path is the **same `McpClient` + `McpTransport` adapter**. Do not activate `IsolatedMcpClient` as a second protocol core that shrinks the feature set.
- `IsolatedMcpClient` live surface today: `start` / `listTools` / `callTool` / `stop` only (no resources/prompts/OAuth reauth). `McpClient` also has `listResources` / `readResource` / `listPrompts` / `doReauthorize`. After W2, IsolatedMcpClient is a **delegating facade** over `McpClient`; plugin launcher I-stage must construct `McpClient` + isolated transport.
- Catalog YAML `162-mcp-isolated-spawn.yaml` currently claims flag-gated IsolatedMcpClient; live host never reads `MCP_USE_ISOLATED_SPAWN`. I-stage rewrites YAML to the factory path.

### Send failure

- MCP isolated carrier: dead/oversize `send` is typed `Error` (`McpTransport.send` already returns `Error | null`).
- Live bug: `bun-spawner.ts` `createSendBridge` drops oversize/dead stdin with warn+return (void). Isolated MCP mode must not silent-drop.
- Non-MCP DXT plugin `IsolatedProcess.send` may remain NO-THROW for that plugin contract; MCP mode maps drop → Error.

### HTTP reauth

- generation-scoped, single-flight.
- Order: create → start → initialize → initialized notification → negotiated state publish.
- initialize-in-flight 401 must not recurse into the same refresh.
- New session id. Do not transplant old session id onto the candidate (`http-sse.ts` first-wins `sessionId === null` is correct for a **fresh** transport; replacement must be a new instance then initialize).
- Replay: proven auth rejection only. Never auto-replay completed-unknown `tools/call`.
- old close/DELETE must not DELETE the adopted session (close old transport only after publish, or skip DELETE when session was handed off).
- Failed/stop: close candidate. Stale responses must not overwrite new state.
- Old pending requests **fail** (do not hang on the rebuilt carrier).

### Replay allow list

- Allowed: idempotent initialize/list that failed with 401 before the new session published.
- Forbidden: `tools/call` whose completion is unknown.
