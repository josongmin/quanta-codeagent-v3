# ADR-0012: 전역 LoC 예산 철회

- **상태**: Accepted
- **날짜**: 2026-05-19
- **관련**: RFC-0001 §1.1·§1.2·§8, RFC-0002 §1.1, ADR-0008·ADR-0011

## 결정

본 레포는 **전역 코드 줄 수(LoC) 상한을 두지 않는다**. RFC-0001 v0.1의
"20k LoC 미만", §8의 Phase별 ~k LoC·"31배 가벼움", RFC-0002의 "<20k"
anti-bloat 표기는 **모두 폐기**한다.

**대신 유지하는 게이트**:

1. 슬라이스 격리 (`@/agent`만 교차 import, Biome `overrides[]`)
2. 신규 npm 런타임 의존성 최소화 (기능별 dep 0 우선)
3. env-gated 기본 OFF + store/포트 미주입 시 루프 동작 보존
4. 결정론 단위/통합 테스트 피라미드

## 배경

초기 RFC는 v2(406k LoC) 트라우마 대비 anti-bloat로 20k 캡을 뒀다.
ADR-0008·0011에서 SOTA++ 흡수 시 LoC 강박은 이미 공식 폐기됐으나 §1.1·§8
등에 잔존 문구가 남아 있었다. 코드·테스트·리뷰 문서가 성장한 뒤에도
상한은 더 이상 의사결정에 쓰이지 않는다.

## 근거

- SWE-bench·관측·subagent/skill 등은 LoC 예산 없이도 슬라이스·테스트로
  통제 가능하다.
- LoC 캡은 "얼마나 가벼운가" 대신 "얼마나 동작하는가"와 어긋난다.
- `docs/reviews-claude-agent/` 등 참고 문서는 LoC에 포함되지 않아도 된다.

## 트레이드오프

- **얻은 것**: 기능·테스트·문서 추가 시 인위적 분할·우회 불필요.
- **비용**: v2식 비대화 재발 위험 — **완화**: 슬라이스 격리·ADR·dep 게이트
  유지, Phase는 Done 정의로만 범위 관리.

## 대안

- **20k 하드 캡 유지**: 기각 — SOTA++·관측·벤치가 이미 초과, 캡은 사실상 무의미.
- **소프트 목표만 문서화**: 기각 — 드리프트 시 또 다른 "정직한 재기" 논쟁만 남김.
